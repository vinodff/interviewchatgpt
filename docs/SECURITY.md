# Security and operational behavior

Local testing deliberately grants one selected existing workspace automatic access and unlimited application minutes. `LOCAL_TEST_MODE` defaults off and is refused in production/staging and the container API entrypoint. Use only the supported loopback launchers: `python -m scripts.run_local` binds 127.0.0.1 and disables forwarding-header processing; frontend dev/start also bind 127.0.0.1. Never expose testing through LAN, public proxies/tunnels or a custom Uvicorn configuration. The peer-based check requires the supported transport; forwarded-header rewriting would invalidate that boundary. Android USB testing uses `adb reverse` without making the services public. Private sessions, owner-bound tickets, consent, file safeguards and request limits remain enforced. Billing and account deletion are disabled. Set testing false before a hosted deployment.

Accounts use Argon2 password hashing and random opaque HTTP-only SameSite cookies. Sessions are stored as hashes and can be revoked. Mutations require an explicit application header and trusted origin; production requires an Origin. WebSocket connections require a valid owner/session-bound, one-use expiring ticket, the authenticated cookie, and an allowed Origin. Authorization is rechecked while running.

Private resources are queried by owner. Encrypted file paths are generated IDs within one validated storage directory. Downloads require authorization and use attachment disposition. Uploaded extensions, content signatures, ZIP paths, compression ratios, expansion limits, image dimensions, PDF pages, scanned-page bytes, and extracted text are bounded. Actual HTTP bytes are capped before multipart parsing, including requests without Content-Length; anonymous uploads are rejected before reading the body. Secret file names and private key material are rejected or redacted during ingestion. No source code or uploaded scripts are executed.

GitHub requests use fixed provider hosts and bounded APIs, never arbitrary URLs from responses. Only public repositories may be imported, including when an operator token is configured. OAuth state is single-use and browser/session-bound. Only identity is persisted after the OAuth exchange; the token is discarded. Commit evidence only verifies the specific signed commit, not the whole repository or the accuracy of its commit message.

Stripe signatures are verified before processing. Duplicate event IDs are idempotent. The handler locks the customer-associated account before fetching authoritative current subscription state, preventing late events from restoring stale access. Provider timeouts are bounded. Checkout reuses existing unpaid sessions. Account deletion preserves access when subscriptions can still bill; open checkout sessions are expired and subscription state is checked again before deleting the customer association.

Files and knowledge go to Gemini only as required for extraction, embedding, and answers. Consent must be appropriate for the interview or meeting and include permission for AI assistance. Raw audio is processed ephemerally; transcript retention is a separate visible choice. Participant consent and browser permissions remain the user's responsibility. The product does not bypass browser capture indicators, interview rules, or recording restrictions.

Operational controls outside application code include host hardening, provider account permissions, encryption key backup, database/file backups, monitoring, TLS/DNS configuration, and capacity testing. Do not infer a production security certification from the test suite.
